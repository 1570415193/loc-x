# loc x 0.3.6

目标设备：iPhone 7 / iOS 15.8.5 / TrollStore。App 内置本机网络扩展、HTTPS 代理和 wloc 重写脚本，不依赖其他代理 App 或电脑常驻运行。网络定位方案不保证覆盖所有 App，也不替换 GPS。

## 使用

1. 用 TrollStore 安装 `loc-x-0.3.6.tipa`。普通版需要 TrollStore 的 ldid；可选的 presign.py 可生成不依赖手机 ldid 下载的预处理版本。
2. 输入城市、地址或地标时从下拉候选中选择位置，也可点击键盘“搜索”获取结果；也可直接点击地图选点，再点“修改”。App 自动验证证书、读取规则状态、在需要时备份并修改可识别的单条定位规则、创建 VPN 配置并启动本机代理。
3. 查看结果。成功首先代表运行中的代理已确认本次坐标；只有收到真实网络定位响应并完成重写，才会显示实际重写数量。请再到目标 App 检查位置。

首次证书安装与完全信任、系统 VPN 授权必须由用户在系统界面完成。证书未信任时提供安装入口，返回 App 后自动复查并继续，不修改证书信任数据库。规则修改后需要手动重启；App 记录当前启动会话，未重启前不继续启用代理。

“恢复真实定位”停止代理。详情菜单提供运行信息、地图重试和从本机备份恢复目标证书规则；停止代理与恢复规则是不同操作。

## 地图

搜索框使用系统 MapKit 地点补全与搜索服务。输入停顿 0.3 秒后显示最多 12 条城市、地址或地标候选，列表最多同时显示四行并可滚动；点击候选后解析位置。取消、改字、重新搜索或开始修改会丢弃旧回调，不会被迟到结果覆盖。搜索文本发送到系统地点服务，需联网，其可用性与高德瓦片独立。选择结果只更新目标位置，仍需点击修改才启用。

- 使用随包携带的 [Leaflet 1.9.4](https://github.com/Leaflet/Leaflet/releases/tag/v1.9.4)，底图不调用苹果地图瓦片服务或在线 JavaScript CDN。
- 按用户需求只保留高德街道图，默认使用原有高德域名的 `style=7` 路网瓦片，移除卫星及其他图源选择。使用 HTTPS，不改变 TLS 验证。地图点击只接受已加载出图像的瓦片；图源不可达时提供重试提示。
- 内部目标坐标始终为 WGS84。高德按照原版 gcj-browser.js 的公式进行显示与点击双向换算，重新加载地图不会改变已选 WGS84 位置。可选“坐标”入口用于跳转。
- 瓦片由原生 NSURLSession 请求，标明 App User-Agent，遵守 HTTP 缓存，不预下载或离线抓取地图；界面持续显示来源归属。
- 地图服务会收到当前浏览区域的瓦片请求。不会向地图服务发送证书、密钥、规则数据库或诊断日志。
- “当前位置”按钮按需请求系统前台定位权限，用蓝点标记并居中，不更改已选目标、不启用代理。系统返回的坐标转换为高德显示坐标；仅接受时间不超过 30 秒且坐标/精度有效的数据，20 秒获取超时后可以重试。拒绝或限制权限时提示系统设置入口路径，不请求后台/始终定位权限。
- 当前蓝点表示系统返回值；代理开启时该值可能已受网络定位修改影响，不能将其称为真实 GPS 位置。坐标只保存在本次界面内存中，地图服务仍会收到浏览区域对应瓦片请求。
- Leaflet 与 wloc 坐标换算来源和许可证随地图资源保留。

## 自动检查与失败处理

- 目标规则不存在时直接跳过写入，不创建或伪造原始恢复基线。
- 写入仍要求完整性、实际表结构、目标唯一性、策略格式、权限和本机备份校验。v131 格式检查用于初始本机基准，不是官方策略指纹白名单。
- 新内容版本仅在与此前本机 v131 基准逐字节一致时接受，命令绑定版本与 SHA-256，事务内再次核对；其他变化拒绝写入。
- 新一次修改复用已连接的本机代理，直接同步并核对目标；已有连接正在建立时等待，不先将它停止。拒绝旧操作的异步回调。只有尚未连接的启动等待超时才取消启动；已连接但坐标确认超时会保留连接并明确显示本次修改未验证、可能仍是旧位置。定位请求失败也不等同于 VPN 故障，会保持连接并展示具体错误。已有配置直接通过 startTunnelWithOptions 传入新坐标，不再 saveToPreferences；只有首次创建才保存和请求 VPN 授权。已存在但禁用或自动启动失败时提示系统手动连接，返回后复查证书/规则、下发并核对当前坐标。扩展私有容器保存最近成功使用的坐标，之后从系统设置启动时优先使用该坐标，兼容旧配置首次迁移。
- 不自动重启手机、终止 trustd/locationd、越狱、关闭 TLS 验证或替换整个规则数据库。
- 策略备份按内容版本区分，包含本机范围和策略指纹。恢复不从其他设备或其他版本补入规则。旧备份无元信息时不能充当新版本可信基准，不会覆盖或删除。

## 构建

需要 macOS、Xcode 和 OpenSSL 3。构建使用 clang、codesign、actool，图标由 AppKit 矢量绘制，无开发者账号要求。普通侧载不保证支持这些权限。

```sh
WLOC_KEYS_DIR=/path/to/private/keys python3 build.py
node Tests/test_map.cjs
python3 Tests/test_rewrite.py
python3 Tests/test_vpn_reuse.py --device <已启动的模拟器UDID>
python3 Tests/test_layout.py --device <已启动的模拟器UDID>
```

默认私钥目录 `build-private/`，可用 `WLOC_KEYS_DIR` 指向此前使用的私有目录，更新时应复用以维持原有证书。根私钥不进入安装包；包内仅有指定定位域名的服务器身份和根证书公钥。根证书有效期 365 天，服务器证书 180 天，过期需重新构建并处理系统证书安装。

需要预处理签名时，先自行从官方 TrollStore 源码构建 fastPathSign：

```sh
python3 presign.py /path/to/fastPathSign loc-x-0.3.6.tipa
```

来源：https://github.com/opa334/TrollStore/tree/main/Exploits/fastPathSign 。此前验证的 TrollStore 提交为 `88424f683b2a08f34a3f88985f790f97d84ce1df`，ChOma 为 `964023ddac2286ef8e843f90df64d44ac6a673df`。这不是 Apple 开发者签名或 macOS 公证。

## 0.3.4 VPN 断开修复

用户截图显示规则检查通过、目标不存在，随后 App 的代理连接/坐标核对超时。代码检查确认旧版每次修改先请求停止旧连接，且确认超时不区分连接状态就再次停止；这能造成用户看到的主动断开，但不证明所有启动失败均由此引起。

生产 VPNLifecycle.h 已加入回归测试：旧行为测试失败；修改后已连接时复用、连接建立中等待、状态确认超时不停止已连接 VPN 的策略测试通过。App 增加 VPN 状态变化、每次主动断开的明确原因、自动连接错误域/编号；扩展通过系统日志记录导入身份、监听、网络设置完成等启动阶段。

0.3.4 已完成编译和签名，真机扩展能否启动、更新坐标及真实重写仍需安装后验证。没有把未确认坐标当作成功，也未改动证书信任、规则数据库算法或强制终止系统服务。

## 0.3.5 本机坐标通信与下拉搜索

- 用户确认系统显示 VPN 已连接，但旧版依赖扩展消息回调，持续无法确认坐标。本版用独立的 127.0.0.1:8878 控制监听器直接读取正在运行的 WLOCProxy，不依赖 sendProviderMessage 来确认成功；8877 继续只代理指定定位域名。两个端口均只绑定本机回环。没有改动系统证书信任或新增外部代理。
- 控制密钥在手机生成，主 App 和扩展各自私有存储保存。请求及响应使用 HMAC-SHA256 双向认证，密钥不在网络上传送；请求 nonce 和时间窗口防重放，坐标命令序号拒绝乱序旧更新。状态包含明确 ready 标志、目标和修订号；只有系统仍已连接、代理网络设置就绪并回传相符目标时才显示代理启用成功。实际定位响应重写仍另行计数。
- 控制监听器有独立并发额度，定位 TLS 请求占满代理槽不影响坐标确认。目标变化会重置计数，旧目标正在处理的响应不能增加新目标的重写计数。
- 若连接中仍运行旧版扩展，会有一次明确提示的停止/启动以加载新通信代码，同一次修改不循环重启、不重复创建 VPN 配置。单纯缺少确认不会视为已成功修改。
- 真实本机代理集成测试通过：身份导入/两个监听器启动、认证状态读取、就绪标志、坐标更新与回读、错误密钥、重放拒绝、乱序命令拒绝、占满数据槽时控制仍响应，以及伪造本机响应拒绝。测试在 macOS 上运行生产 Proxy.m / LocalControl.m，PKCS12 仅导入内存，不写系统钥匙串。该测试不能代替 iOS 扩展生命周期的真机验收。
- 生产 JavaScriptCore 正/零/负坐标及未知响应回归通过。输入下拉 UI 已编译，系统搜索网络服务及真机显示仍需安装后验证。

新增测试：`python3 Tests/test_control.py`，仅本机回环网络，不创建系统 VPN 或改手机数据库。

## 0.3.6 名称与成功提示

桌面显示名、应用内标题改为 loc x；Bundle ID、扩展 ID 和证书继续使用原有标识，便于覆盖安装和复用既有配置。

从系统设置返回时重新加载 VPN 配置并核对本机代理。过时的状态错误仅记录运行日志；正在确认或此前已确认的目标，在系统仍连接时得到新的核对窗口，避免后台计时造成误报。真实断开、代理身份/坐标不符仍会明确显示。App 无法屏蔽 iOS 自身拥有的 VPN 弹窗。

每次“修改”经代理就绪及坐标核对成功后，仅弹出一次提示：请到 设置 → 隐私 → 定位服务，手动关闭再重新打开定位服务；成功区也保留同样说明。不会自动切换系统定位服务，返回设置不会重复弹出同一次修改的提示。

通过编译、签名和生产前台恢复策略回归（连接中待核对目标、已确认会话恢复、无目标不自动套用、真实断开不隐藏）。实际设置返回与弹窗展示仍需 iPhone 验证。
