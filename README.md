# WLOC 独立版 0.1.1

目标：iPhone 7 / iOS 15.8.5 / TrollStore。本机运行，不依赖外部代理 App、快捷指令或 Worker。

## 已实现

- 中文原生界面：地图长按选点、地点搜索、WGS84 经纬度输入。
- App 内网络扩展与回环地址 HTTPS 代理，仅接受五个 WLOC 目标域名的 CONNECT，拒绝其他目标。
- 原样内嵌 wloc 脚本，以 JavaScriptCore 执行二进制网络定位响应重写；已连接时可直接更新目标。
- “恢复真实定位”停止本机代理，与恢复证书规则分离。
- WLOCRules root helper：只读检查、校验版本、备份及事务修改、单条规则恢复；维护操作需在 App 内明确确认。首次启动不修改规则。
- 定位证书按本机构建单独生成，根私钥只保存在工作目录，不放入安装包。安装包仅携带服务器身份和根公钥。证书需手动安装和信任。
- 状态展示连接、请求、实际重写及错误计数，连接成功不代表定位生效。

## 安装与验证顺序

1. 将 WLOCStandalone-0.1.1.tipa 交给 TrollStore 安装。
2. 打开 WLOC 定位，运行“检查规则（只读）”，保留输出。要求 schema 3、实际表结构符合预期、目标规则唯一且具有访问权限。v131 保留原项目的格式检查作为本机初始基准；这不是官方策略指纹白名单。首次成功修改时将基准与备份元信息一起保存。新内容版本必须与本机此前保存的 v131 基准逐字节一致，并经额外确认，否则拒绝写入。
3. 通过 App 导出证书描述文件，存入“文件”后打开，在系统设置安装，并在“关于本机 → 证书信任设置”中手动信任。首次证书安装流程需实机确认。
4. 若目标规则存在，在了解影响后点击“备份并应用 WLOC 规则修改”，手动重启并重新检查。该步骤会改变相关 Apple 定位域名的证书固定校验。
5. 输入 WGS84 位置，点击“应用位置”，首次允许系统创建 VPN 配置。不要同时开启其他 VPN。
6. 在地图触发网络定位，核对请求和重写计数，再核对实际位置。网络定位覆盖受 wloc 机制限制，不承诺所有 App 或 GPS 生效。
7. 点击“恢复真实定位”停止代理；定位缓存可能需要时间刷新。单独点击“恢复原始证书规则”并重启可恢复规则，不会回滚整个数据库。

## 当前验证结果与限制

- iOS arm64 两个可执行文件编译通过，部署目标 iOS 15.0，包内签名和 DER 权限检查通过。
- macOS JavaScriptCore：正坐标、零坐标、负坐标二进制重写通过；不认识的响应保持原样。
- 一次实际 TLS 集成测试：通过本地代理访问 gs-loc.apple.com 收到上游 HTTP 404（根路径非 WLOC 接口），TLS 验证未关闭；非目标 example.com 的 CONNECT 返回 403。
- 临时数据库：只读检查、备份、修改、恢复、重复操作、异常版本、锁冲突、符号链接拒绝、WAL 快照恢复通过。
- 数据库便携测试仅在临时副本中跳过 root 入口条件；生产代码仍强制 root。未以这些测试代替手机权限验证。
- 新增兼容性回归：缺少基准拒绝、新版本明确确认、同长度策略变化拒绝、跨设备基准拒绝、恢复元信息不符拒绝、schema 编号未变但列结构变化拒绝、触发器拒绝。
- 尚未验证本机 iPhone 上网络扩展的注册/启动、实际 trustd 数据库读写、证书安装和真实定位效果。0.1.1 是待实机验收版本。0.1.0 的旧备份不含元信息，不能自动作为新版本的可信基准；不会覆盖或删除旧备份。
- 大陆地图选点当前按 GCJ-02 近似转 WGS84；地图服务的坐标语义仍需实测，精确位置可直接输入 WGS84。
- 当前代理只支持 HTTP/1.1 CONNECT、Content-Length 请求体；单次响应上限 2 MB，超时或异常会记录失败。不支持 UDP/QUIC 拦截。
- 根证书有效期 365 天，服务器证书有效期 180 天；到期需更新构建。根私钥不在 App 中，App 无法签发其他域名证书。

## 构建

Mac 上安装 Xcode 命令行工具和 OpenSSL 3 后：

```sh
python3 build.py
python3 Tests/test_portable_rules.py
python3 Tests/test_rewrite.py
```

build.py 直接调用 Apple clang 和 codesign，不需要开发者账号；结果用于 TrollStore。普通侧载不保证支持所需权限。build/ 是生成目录，重建会更新安装包。第三方来源及本地修改记录见 Vendor/PROVENANCE.md。

## 后续实机验收

安装并打开 → 只读检查规则 → 验证 VPN 扩展能启动 → 手动信任证书 → 用户确认后修改规则并重启 → 验证实际 WLOC 请求与坐标 → 验证停止代理与规则恢复。

不要仅凭编译成功或 VPN 图标认定定位修改成功。

## 0.1.1 规则兼容性与备份

- “检查规则”可报告较新的内容版本；写入仍要求 schema 3、准确列定义、真实表、无触发器、完整性正常和唯一目标。
- 策略 SHA-256 用于展示和绑定确认；新版本是否兼容最终用完整策略字节比较，而不是只看数据长度。
- 新版本写入的确认绑定当时看到的内容版本和 SHA-256。提交前在事务内重新核对，避免检查后数据库变化。
- 每个内容版本分别保存备份，记录格式、内容版本、设备本地令牌/机型/系统构建范围和策略指纹。恢复只使用同内容版本、同设备范围且元信息一致的备份，不将旧版本规则插入新版本数据库。
- Root 私有令牌仅在初始 v131 写入流程中建立；只读检查不创建令牌。该机制验证本机历史一致性，不证明该策略由 Apple 发布。
- 本轮不自动终止 trustd，也不提供未经实机权限验证的刷新按钮；仍提示手动重启后验证。
- 安装出现 Error 173 时，先在 TrollStore → Settings → Install ldid 安装其官方签名工具，再重试本包。普通 Apple 开发签名不是 TrollStore 权限安装的替代方案。

## 私钥与分发

构建默认将根私钥存入 `build-private/`，此目录和所有安装包、证书及数据库都被 Git 忽略。也可通过 `WLOC_KEYS_DIR` 指定仓库外的私有目录。不要将根私钥推送到仓库。
本仓库交付源码，不发布已经启用证书信任或已修改设备规则的配置。WLOCRules 尚无明确许可证，其来源代码单独保留归属；公开再分发前需确认上游授权。
